# RailRakshak AI — Database Architecture

The RailRakshak AI platform uses SQLite for local development, prototype demonstrations, and edge deployments, managed through `backend/database.py`.

## Database File
- **Default Location**: `backend/railrakshak.db`
- **Configurable via**: `DB_PATH` environment variable in `.env`

---

## Schema Overview

### 1. `defects` Table
Stores raw and classified railway defect telemetry generated by the YOLO vision pipeline and sensor systems.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | TEXT (PK) | Unique defect identifier (e.g. `DEF-001`) |
| `inspection_id` | TEXT | Linked inspection run identifier |
| `defect_type` | TEXT | Defect classification (`Rail Fracture`, `Missing Fastener`, `Surface Crack`, `Sleeper Damage`) |
| `confidence` | REAL | Detection confidence percentage (0 - 100) |
| `risk_score` | INTEGER | Calculated operational risk score (0 - 100) |
| `severity` | TEXT | Risk severity classification (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`) |
| `latitude` | REAL | GPS latitude coordinate |
| `longitude` | REAL | GPS longitude coordinate |
| `timestamp` | TEXT | ISO-8601 timestamp of occurrence |
| `status` | TEXT | Lifecycle state (`IDENTIFIED`, `INVESTIGATING`, `SCHEDULED`, `RESOLVED`) |
| `image_url` | TEXT | URL path to stored snapshot image |
| `section` | TEXT | Track zone/corridor identifier (e.g. `North Corridor - Track A`) |
| `recommended_action` | TEXT | Automated safety advisory from risk engine |
| `bbox` | TEXT | Serialized bounding box `[x, y, w, h]` |

---

### 2. `maintenance_tasks` Table
Tracks dispatch actions and remedial work orders assigned to maintenance personnel.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | TEXT (PK) | Task identifier (e.g. `TSK-101`) |
| `defect_id` | TEXT (FK) | Reference to `defects.id` |
| `defect_type` | TEXT | Cached defect type for fast querying |
| `severity` | TEXT | Defect severity level |
| `section` | TEXT | Assigned track section |
| `status` | TEXT | Task state (`PENDING`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`) |
| `assigned_to` | TEXT | Crew / Engineer name |
| `deadline` | TEXT | Targeted completion date |
| `created_at` | TEXT | ISO-8601 task creation timestamp |
| `notes` | TEXT | Field engineer notes and updates |

---

### 3. `railway_sections` Table
Defines track zones, operational speed limits, and base risk factors for geospatial mapping.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | TEXT (PK) | Section identifier |
| `name` | TEXT | Human-readable section name |
| `zone` | TEXT | Operational administrative railway division |
| `total_km` | REAL | Section track length in kilometers |
| `status` | TEXT | Track operational status (`NORMAL`, `CAUTION`, `RESTRICTED`) |
| `risk_level` | TEXT | Current dynamic hazard rating |

---

### 4. `analytics_cache` Table
Stores precomputed safety KPIs and historical aggregate metrics for fast dashboard rendering.

---
